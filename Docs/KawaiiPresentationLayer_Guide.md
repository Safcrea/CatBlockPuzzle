# Kawaii Presentation Layer Guide

## Scope

This pass only restyles the existing `CatBlockPuzzleGame` presentation. It does not change board data, piece definitions, drag/drop validation, placement rules, level progression, saved progress, or win checks.

## What Changed

- Warm cream full-screen background with a subtle low-noise gradient.
- Safe-area root under the overlay canvas.
- Cream top HUD with large dynamic level title.
- Decorative back, pause, and settings controls styled as touch targets.
- Compact 3-star progress strip.
- Dynamic objective subtitle bound to the active level title.
- Cream board frame with subtle cat ears, face, whiskers, border, and shadow.
- Existing dynamic board cells restyled as soft grey rounded tiles with pale paw prints.
- Bottom tray restyled as a raised cream panel.
- Existing dynamic piece slots restyled as cream piece cards with dotted drag grips.
- Existing cat piece visuals kept shape-driven, but recolored to pink, mint, blue, and yellow palette.
- Existing hint/reset buttons restyled as cream mobile buttons.

## Existing Dynamic Bindings

- Level title: `Level {levelIndex + 1}`
- Objective subtitle: `activeLevel.Title`
- Board dimensions: existing `activeLevel.Rows` and `activeLevel.Cols`
- Board shape: existing `activeLevel.ActiveCells`
- Pieces: existing `activeLevel.Pieces`
- Piece colors: presentation palette only, still assigned per existing piece order
- Hint/reset behavior: existing button actions
- Win panel title/reward: existing win sequence data

## Prefab Structure Recommendations

If this runtime UI is later converted to prefabs, keep logic and visuals separated:

- `PF_HUDButton_View`
  - `Image`
  - `Button`
  - `Text` or `TMP_Text`
  - optional badge child
- `PF_BoardFrame_View`
  - rounded cream image
  - decorative ear/face/whisker children
- `PF_BoardCell_View`
  - background image
  - outline/shadow
  - optional paw child for grey state
- `PF_PieceCard_View`
  - cream panel image
  - centered existing draggable-piece root
  - dotted grip child
- `PF_CatBlock_View`
  - body image
  - ear/inner-ear children
  - eyes/nose/mouth/cheeks/whiskers
- `PF_UtilityButton_View`
  - icon
  - label
  - optional green badge

These prefabs should receive data from the existing gameplay controllers. They should not own board layout, validation, placement, or win state.

## Inspector Hookup Guide

For future prefab-based work, expose references on view scripts only:

- `Image background`
- `Image outline`
- `Image shadow`
- `Image pawIcon`
- `Text/TMP_Text label`
- `Text/TMP_Text countBadge`
- `RectTransform visualRoot`

Core gameplay should call simple visual methods:

- `SetLevelTitle(string value)`
- `SetObjective(string value)`
- `SetCellVisual(BoardCellVisualState state)`
- `SetPieceColor(Color color)`
- `SetBadgeCount(int count)`
- `SetPressedVisual(bool pressed)`

Avoid passing gameplay objects into view scripts unless they are read-only interfaces.

## Swapping Colors Or Art Later

Palette constants are currently in `CatBlockPuzzleGame` and reusable helpers under `Assets/Scripts/CatBlockPuzzle/KawaiiUI/`.

To swap art later:

- Replace generated runtime sprites with imported sliced sprites.
- Keep sprite borders set for rounded panels.
- Keep board paw icons low opacity.
- Keep piece body/face elements as separate children so shape logic remains untouched.
- Use the same `PieceColors` array to change piece colors without changing piece definitions.

## Notes

The current game creates UI in code, so the safest visual change path is styling the creation methods and generated child objects. Converting the screen to prefabs is possible, but should be done by binding prefabs to the existing `CatBlockPuzzleGame` state instead of replacing its placement and validation flow.
